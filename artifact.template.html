The question

Can the model earn a place in this workflow?

A useful recovery assistant needs a reliable next step, traceable evidence and a deployment that the next OEM can afford. This replay tests the first two in a small synthetic setting. Customer demand, support savings and industrial hardware fit remain open.

Original experiment: four methods

  1. Alarm lookup. Uses the current alarm only. This is a narrow reference point.
  2. Decision tree. Receives the complete evidence, including operator notes. Its visible parser handles a limited set of phrases.
  3. LFM with current state. Receives the snapshot and procedure. Missing history often requires a question, so this condition is deliberately disadvantaged.
  4. LFM with full evidence. Receives the same incident information as the tree. This is the model comparison that matters.

The tree directly implements a small authored policy. Its maintenance cost on real procedures has not been measured. These cases cannot establish an advantage over rules.

The original failure stays in the record

We first used 12 development incidents and 24 held out incidents. One prompt revision preceded a frozen final run. The full model returned no usable decisions on those 24 cases. Most calls used the entire answer budget while repeating their reasoning.

Direct selection remained unreliable after output repairs. The revised product design gives LFM one smaller job: extract the displayed recipe and completed checks from the operator note. The deterministic procedure tree then selects the response. The original reasoning template is preserved. Hybrid results measure that complete pipeline and must not be described as model action selection accuracy.

The hybrid evaluation is a separate experiment. The fresh run compares alarm lookup, full evidence rules and the full hybrid; the current state ablation remains available in the original and development runs. Two development runs tested the note extraction interface. A revision restored the model’s native reasoning and increased its generation budget. It uses the original development cases and 24 fresh combinations under the same mock policy. Pairs stay within a split. One author created the data, labels and baseline, so the new holdout is not an independent benchmark. Original held out results remain visible and unchanged.

What the numbers mean
  • Correct next step matches the explicit label before any fallback. It includes questions and escalation types.
  • Strict pass also requires a valid answer and every source marked necessary by the case label.
  • Valid evidence means cited IDs exist in the supplied input. It does not establish universal factual support.
  • Unsupported assertion is a contract violation proxy for malformed output, extra fields or unknown IDs. It is not a factual hallucination rate.
  • Wrong check is a permitted check selected for the wrong situation. These remain visible even if the guard accepts them.
  • Latency measures the complete model call, including input processing and generation. Loading, shared preprocessing and display time are separate.
  • Memory is peak MLX allocation plus a separately reported sampled process footprint. They overlap and must not be added.
The same guard checks all methods. It can reject an invalid selection, but it never replaces a choice with the expected answer. In the hybrid design, the model returns observations only. The rule engine chooses the action, citations and missing information. Extracted observations are also compared with explicit labels on the fresh cases. Neither the rule engine nor the model receives those labels.
